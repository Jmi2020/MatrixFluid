Interfacing the CQRobot Non-Contact Liquid Level Sensor (Type 1, Round) with ESP32

DIP Switch Settings for ESP32 Compatibility

The CQRobot non-contact liquid level sensor (SKU: CQRSENYW001) has two small DIP switches on its adapter board, which must be configured correctly for use with an ESP32:
	1.	Output Voltage (Right DIP) – This switch selects the high-level output voltage on the green signal wire. For an ESP32 (3.3 V logic), set the right-hand DIP switch to the 3V position. In this position, the sensor will output ~3.3 V as a HIGH signal (instead of 5 V) ￼. (When the right DIP is toggled up it outputs 5 V HIGH, and when toggled down it outputs 3.3 V HIGH ￼, so use the 3.3 V setting to protect the ESP32 GPIO.)
	2.	Output Logic Polarity (Left DIP) – This switch inverts or normalizes the output logic. In the default up position, the sensor outputs a HIGH signal on the green wire when liquid is detected and a LOW signal when no liquid is present ￼. If you flip this left DIP switch down, the logic is reversed – the sensor will output LOW when liquid is detected, and HIGH when no liquid is present ￼. For typical use, you’ll want the default (non-inverted) setting so that “wet” corresponds to a HIGH signal.

Output Signal: Fluid vs. No Fluid

With the DIP switches set as above (3.3 V output and non-inverted logic), the sensor’s green output wire will carry a digital signal indicating the presence of liquid. In practical terms, when the sensor detects fluid, the green wire is driven HIGH (~3.3 V), and when no fluid is detected, the green wire is LOW (0 V) ￼. This HIGH/LOW output is basically an on/off indication of liquid presence (the sensor’s internal circuitry handles the capacitive detection and thresholding). The device is designed as an open-collector style output internally ￼, but since the sensor board provides its own pull-up to the selected voltage, it presents a clean digital signal to your microcontroller. The response time of the sensor is about 500 ms ￼, meaning there may be a slight delay (half a second) for the output to change state after liquid contact or removal.

Summary of signal behavior (with default logic): When liquid touches the sensor (or reaches the sensor’s level on the container), the green wire goes HIGH (3.3 V if configured for 3 V output) to indicate “fluid present.” When the sensor is dry (no liquid at the sensing point), the green wire stays LOW (0 V) ￼. If you have the left DIP in the inverted position, this behavior swaps (HIGH = no fluid, LOW = fluid).

Connecting and Reading the Sensor via ESP32 GPIO

Wiring: The sensor has three wires: Red (power), Black (ground), and Green (signal output). Supply the sensor with 5 V DC on the red wire and connect the black wire to ground, as the sensor is designed to run on 5 V input ￼. (Even when using 3.3 V logic output, the sensor’s supply should remain at 5 V for proper operation ￼.) Connect the green wire to one of the ESP32’s GPIO pins that you will use as a digital input. Be sure that the right DIP switch is set to output 3.3 V high, as noted, so that the green wire’s HIGH level is safe for the ESP32’s 3.3 V inputs ￼.

ESP32 Pin Configuration: In your ESP32 firmware, configure the chosen GPIO pin as a standard digital input. You typically do not need any external pull-up or pull-down resistors, because the sensor’s output stage takes care of that (it has an open-collector output with an internal pull-up to 3.3 V or 5 V per the DIP setting) ￼. In code, you can simply do something like pinMode(sensorPin, INPUT) and then use digitalRead(sensorPin) to get the sensor state. The reading will be HIGH (logic 1) when liquid is detected (sensor wet) and LOW (logic 0) when no liquid is detected (sensor dry), assuming the left DIP is in the default position as discussed ￼. If you flipped the logic inversion DIP, remember to interpret the reading accordingly (it would be opposite in that case).

Handling the Sensor Signal in Software: Because the sensor output is a clean digital signal, you don’t need any analog handling or complex signal processing – it’s essentially like reading a button or switch, but indicating water presence. However, given the sensor’s 500 ms response time and the possibility of minor signal noise at the switching threshold, it’s good practice to implement a short debounce or filtering delay in your code. In other words, ignore rapid fluctuations and only treat the signal as changed if it stays high or low for a short period (for example, >100 ms). In ESPHome or similar frameworks, this can be done with software filters (e.g. adding a 100 ms delayed_on and delayed_off filter to the binary sensor) ￼, or in Arduino code you can simply check that the state remains steady for a few readings. This ensures you get a stable reading of “fluid” or “no fluid” from the sensor.

Recap: Set the right DIP to 3.3 V and left DIP to the desired logic (typically non-inverted for HIGH = wet). Power the sensor with 5 V, ground it, and connect the green output to an ESP32 GPIO input. When you apply power, the ESP32 should read a LOW on that GPIO if the sensor is dry, and it will read HIGH once fluid is detected at the sensor ￼. You can then use that digital reading in your firmware to trigger whatever logic is needed for your application (e.g. tank level alarm, pump control, etc.). All in all, the sensor outputs a straightforward digital HIGH/LOW signal that the ESP32 can read directly via digitalRead(), corresponding to “fluid present” or “no fluid” states.  ￼ ￼
